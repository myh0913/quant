# 量化系统项目规范

## 1. 项目定位
- 这是一个全新的量化选股与操作建议系统，不继承 StockSystem 的实现、脚本、数据目录或运行方式。
- 系统只生成股票操作建议，不自动连接券商，不自动下单，不主动执行买卖。
- 最终买卖由用户自行判断和执行；系统必须区分“系统建议”“用户实际操作”“市场结果”。

## 2. 核心设计原则
- 可迁移：代码、配置模板、数据库结构、策略定义、测试和运行文档随项目走；不依赖本机绝对路径、个人环境或隐藏状态。
- 可复现：原始数据、标准化数据、派生数据、因子版本、策略参数和运行时间必须可追溯。
- 程序优先：数值计算、信号生成、仓位计算和风险否决由确定性程序完成。
- LLM 辅助：LLM 只负责解释、摘要、公告结构化和报告表达，不能自行改变信号、仓位或风控结论。
- 风控拥有否决权：任何策略信号都必须经过风险检查后才能形成建议。
- 先验证后扩展：先做最小可运行策略，再做回测、模拟盘、多策略和复杂模型。
- 先规则后模型：第一版不以机器学习或 LLM 决策为核心。

## 3. 必须防范的问题
- 未来函数 / 未来数据泄漏
- 幸存者偏差
- 数据窥探和过拟合
- 复权、停牌、退市、除权除息处理错误
- 财务数据未按实际披露时间对齐
- 忽略手续费、印花税、滑点、涨跌停无法成交和 T+1 约束
- 实时数据过期、缺失或来源异常时仍生成建议

## 4. 系统边界
系统应逐步覆盖：数据采集、数据质量、因子、策略、组合与仓位、风控、回测、模拟运行、建议生成、记录归因、监控运维。

第一版明确不做：自动交易、券商下单、复杂分布式架构、无验证的机器学习预测。

## 5. 可迁移要求
- 配置使用环境变量或配置文件模板，禁止把密钥写入仓库。
- 路径使用项目相对路径或可配置路径。
- 提供一条清晰的初始化、校验、回测、建议运行流程。
- 新电脑能够通过项目文档完成安装和运行。
- 外部数据源必须有适配器，不得把供应商调用散落在策略代码中。

## 5.1 环境变量与密钥管理（2026-09-05 用户确认）
- 项目使用 `.env` 文件集中管理环境变量（模板见 `.env.example`，`.env` 已被 `.gitignore` 忽略）。
- API Key 等密钥只由用户在宿主机侧写入 `.env`，助手不得将密钥明文写入命令、日志、项目文件或对话。
- 代码通过标准方式加载 `.env`（如 python-dotenv），加载失败时给出明确错误而不是静默空跑。
- 迁移到新机器时，拷贝 `.env.example` 为 `.env` 并重新填入密钥即可，仓库内不保留任何真实密钥。
- 第三方数据源的官方用户级凭据文件（如 hithink-finance 的 `credentials.env`）同样不入库，由用户侧维护。

## 6. 数据源评估硬标准
数据源必须可以被项目代码脚本化调用，不能依赖人工打开网页、手工导出或临时复制数据。

每个候选数据源必须分别评估：
- 数据完整性：是否覆盖策略需要的原始字段，不能用近似字段冒充。
- 时间准确性：字段的实际生成时间、可见时间和数据时间戳。
- 历史覆盖：是否覆盖 2024-10-20 至当前，是否能按当时可见信息回放。
- 延迟：请求延迟、数据生成延迟和盘中刷新频率。
- 并发：批量能力、并发上限、限流、重试和连接复用。
- 稳定性：连续运行、空值、断线、错误响应和恢复能力。
- 可迁移性：Python/HTTP/协议依赖、系统平台和部署难度。
- 授权与合规：使用限制、账号权限、商业/研究限制和凭证管理。

策略要求必须逐字段验证。不得把收盘后数据替代盘中数据，不得把竞价结果替代 9:20/9:25 快照，不得把文档宣称标记为实测可用。

## 6.1 接口文档标准（2026-09-06 强化）

所有接口文档必须做到"不依赖当前会话记忆即可复现"，具体标准：

- 请求：完整 URL、方法、必填/可选参数表（名称、类型、默认值、示例值）、请求头、鉴权方式。
- 响应：顶层结构示例 JSON、每个字段的名称、类型、单位（元/手/股/小数 vs 百分数）、时间戳语义（Unix 秒 vs 毫秒、时区、是数据时间还是响应时间）、可空性。
- 嵌套对象：单独列出子结构，给出实测样例 JSON，不能只写"股票数组"。
- 每个字段标注实测状态：✅ 已实测 / ⚠️ 语义待观察（给出待确认点）/ ❌ 不可用。
- 单位陷阱必须显式标注，例如 `change_percent` 是小数（0.1999=+19.99%）、`core_avg_pcp` 是小数（0.05539≈+5.539%）。
- 每一节标注：实测日期、数据源域名、用途、已知限制、未验证项。
- 严禁把"猜测的字段语义"写成事实；不确定就写"待验证"，并指出验证方法。

项目内所有接口文档（DATA_SOURCE_RESEARCH.md、DATA_CONTRACT.md、skill 文件）统一执行本标准。写完后自查：一个新会话的 agent 只看这份文档能否直接写出正确的适配器代码？不能则补全。

## 7. 研发流程
每个阶段按“规格 → 实现 → 测试 → 样例运行 → 记录进度”完成。
大改动先给出方案并等待用户确认；完成后汇报新增、修改、验证和回滚方式。
每次继续项目时，先阅读本规范、PROJECT_STATUS.md 和产品技术规格书，再开始工作。

## 7. 建议输出标准
每条建议至少包含：股票标识、建议动作、触发时间、参考价格或条件、建议仓位、止损/失效条件、有效期、依据因子、风险拒绝或限制原因。
