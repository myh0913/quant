## 1. 结论摘要

当前最值得优先实测的是 `eltdx`，原因是其公开接口目录明确覆盖：集合竞价过程、历史竞价、实时行情、分钟线、财务基础、个股题材、短线指标和连板天梯等能力。

`xuangutong-data` 适合作为情绪、涨停池、炸板池、昨日涨停表现、涨停原因和题材关联数据源；但当前资料明确显示，它不能作为精确集合竞价 9:20/9:25 全市场成交额排名的唯一来源。

`pytdx3` 是基础 TDX 协议客户端，适合行情、K 线、分时、分笔、财务和板块文件；`tdx_quant` 是基于 pytdx 的数据管道和研究样例；`thspypc` 能力很广，但依赖同花顺协议登录/权限，适合作为受控实验数据源；`pywencai` 适合低频补充查询，不适合实时主链路。

当前不能仅凭 README 认定任何数据源已经满足生产要求。需要对关键接口逐项保存原始响应、字段映射、时间戳和失败情况。

## 3. 已审阅资源

### 3.1 选股通 skill

已知能力：

- 市场温度、涨跌家数、涨停/跌停/炸板率。
- `limit_up`、`limit_up_broken`、`yesterday_limit_up`、`super_stock`、`limit_down` 等池子。
- `limit_up_days`、封单比、炸板次数、封板时间线、涨停原因、相关板块、换手率、量比、市值、上市日期等字段。
- 支持历史交易日池子查询，可用于重建情绪周期和连板表现。
- `/live`、`/jihui`、`/ts/home` 等页面可提供快讯、机会、题材和研报内容。

限制：

- 资料记录显示竞价数据存在 9:25 整点延迟，通常需要 9:27 后二次获取。
- 不能把其池子接口当作全市场竞价成交额排名接口。
- 历史新闻、监管事件和财务数据的 point-in-time 能力尚未确认。

### 3.2 pytdx3

README 和代码说明其目标是纯 Python TDX 行情接口，包含：

- 日/周/月及分钟 K 线。
- 实时行情和五档盘口。
- 当日/历史分时。
- 当日/历史分笔。
- 股票列表、指数 K 线。
- 财务信息、公司信息、除权除息。
- 板块文件解析。

尚未证明：精确 9:20/9:25 竞价过程、历史竞价、监管、新闻和连板榜单。

### 3.3 tdx_quant

这是一个基于 pytdx 的数据管道样例，值得借鉴的内容：

- 按股票和数据域落盘 Parquet。
- 日线、分钟线、除权除息、分笔、分时、财务和证券列表任务。
- 指标计算和声明式选股。
- 数据下载、标准化、缓存与前端导出。

它更适合参考工程组织方式，不应直接当作本项目的业务实现或数据能力证明。

### 3.4 eltdx

公开文档明确列出的能力包括：

- 批量实时行情和五档盘口。
- 分类行情，可按涨幅、价格、成交额等排序。
- 分钟/日/周/月等 K 线和复权。
- 当日/历史分时。
- 当日/历史成交明细。
- 集合竞价过程，包含历史日期参数。
- 09:25 正式撮合筛选。
- 财务基础信息、股本变迁和 F10。
- 个股题材、短线指标、实时榜单、连板天梯、题材强度。
- MCP、HTTP 和 WebSocket 适配。

这是最贴近当前三种短线策略的候选，但“文档声明”必须转化为接口实测结论。

### 3.5 thspypc

公开文档列出的能力包括：

- 全市场股票列表和快照。
- 1/5/15/30/60 分钟及更高周期 K 线。
- 当日/历史分时。
- 早盘和尾盘竞价。
- 竞价金额、开盘价和涨幅等行情字段。
- 短线异动、实时推送、板块和板块成分。
- DDE 排名、批量资金字段、总市值。
- 逐笔成交、盘口回放和 Level2 队列（部分依赖权限）。

限制：

- 需要登录或二维码凭证；能力依赖账号等级。
- 具有研究用途和第三方服务使用限制，必须单独评估授权、稳定性和合规性。
- 不应把账号凭证写入项目或中间产物。

### 3.6 pywencai

公开文档显示：

- 通过自然语言查询问财结果。
- 可排序、分页、循环分页、指定股票优先。
- 当前需要 cookie。
- 请求频率过高可能被屏蔽。

适合：低频条件筛选、补充字段和研究阶段查询。

不适合：集合竞价实时主链路、分钟级轮询、需要严格 point-in-time 的核心回测。

## 4. 三个策略的数据可行性初判

### 策略一：竞价主力抢筹

必要数据：全市场/股票池竞价成交额、9:20 价格、9:25 价格、昨收、竞价涨幅、时间戳。

初判：

- `eltdx`：最有希望，文档明确有集合竞价历史过程；必须实测历史日期是否含 9:20/9:25 价格、量、额。
- `thspypc`：最有希望之一，文档明确早盘竞价，但登录和权限是风险。
- `pytdx3`：基础行情可用，但竞价过程未从 README 证实。
- 选股通：只能作为交叉校验，不应作为唯一竞价数据源。
- `tdx_quant`：可作为批量落盘模板，需依赖底层接口补竞价。

当前不能回测的关键原因：没有确认 2024-10-20 至今的逐日历史竞价快照覆盖。

### 策略二：连板捉妖

必要数据：历史涨停/连板、首板和第一波识别、成交量倍数、一字板、昨日连板成功率、跌停数、题材主线、分钟级开盘行为。

初判：

- 选股通历史池子可以支持涨停池、连板数、封板状态和涨停原因的基础重建。
- TDX/eltdx/thspypc 可补日线、分钟线、分笔和竞价。
- “第一波”“三板组”“分时快速/墨迹”“主线持续性”仍需正式定义，不能直接依赖自然语言。

### 策略三：龙回头

必要数据：历史连板、首次调整、日线形态和成交量、次日竞价、分钟级承接/横盘、跌停封单、情绪和板块分散度。

初判：

- 日线、分钟线、分笔和基础盘口理论上可由 TDX/eltdx/thspypc 组合支持。
- 历史连板候选和题材关联可由选股通补充。
- “出货”“承接”“横盘位置”“砸得快”等需要先设计可计算代理指标和人工复核标签。

## 7. 2026-09-05 后续实测补充

### TDX Finance MCP 插件：已验证可脚本化调用的能力

通过现有工具完成真实请求，结果不是仅依据 README：

- `tdx_screener` 能返回竞价成交额排序，字段显示为按日期的“开盘金额”；历史日期 `2024年10月21日 竞价成交额` 返回 5548 条记录。该能力高度匹配策略一，但仍需在正式适配器中确认排序语义、股票池过滤和字段单位。
- `tdx_screener` 历史涨停查询可用：`2024年10月21日 涨停` 返回 187 条，并含首次涨停时间、连续涨停天数、几天几板、板型、涨停成交额、封单金额、封单量、涨停打开次数和涨停原因。
- `tdx_screener` 当前涨停/跌停/炸板/昨日连板查询可用，字段可支撑情绪和连板统计；自然语言查询必须固定模板并做结果校验，不能把自然语言接口当作无契约数据接口。
- `tdx_kline` 1 分钟线可用。实测 `startxh=1800` 返回 2026-08-26，`startxh=20000` 返回 2026-05-11；日线 `startxh=470` 返回 2024-09-24。因此日线覆盖目标区间已初步满足，分钟线至少有数月级历史深度，但完整深度、逐股一致性和分页规则仍需系统测试。
- `tdx_quotes` 实测返回实时行情、竞价成交额 `ProInfo.OpenAmo`、开盘换手 `CalcInfo.CAKPHSZ`、涨停价等字段；非交易时段的数据时间必须严格检查。
- `tdx_api_data` 热点题材板块族谱和涨停分析真实请求成功，约几十毫秒级；可作为题材/涨停辅助源。
- TDX 插件支持的工具/接口是 OpenClaw 工具封装；项目迁移时不能依赖 Agent 工具本身，必须评估是否能通过独立 HTTP/SDK/协议适配器脚本调用。

### TDX 实测仍需注意

- “2024年10月21日 竞价成交额”成功，证明历史结果可查询，但尚未证明该结果同时包含策略一所需的 9:20 价格快照。
- `tdx_screener` 的自然语言查询返回字段很丰富，但必须保存原始查询文本、结果日期、headers 和原始数据；不能依赖列名长期稳定不变。
- 1 分钟 K 线历史深度目前只用单只股票的偏移抽样证明，尚未证明所有主板股票都覆盖到 2024-10-20。
- 选股结果包含 002/003 等代码，正式项目必须按用户确定的股票池规则显式过滤，不能只依赖“主板”自然语言。

### Financial API / hithink-finance 项目：文档和 CLI 验证

- 已克隆并审阅 `https://github.com/hithink-tech/financial-api`。
- 官方 CLI 源码可在本地安装构建，`capabilities --format json` 成功返回机器可读能力目录。
- 目录共覆盖 59 个能力，包含行情、日线、财务、估值、交易日历、集合竞价、指数/板块、涨跌停/炸板/连板天梯、异动、热榜、龙虎榜、Market Dumps、本地 DuckDB 和导出。
- `market.auction-snapshot` 明确为 `today-only`；公开快照端点没有历史日期参数。`market.auction-benchmark` 可按日期查询，但不是完整的 9:20/9:25 成交额快照。
- `market.history` 当前公开契约只支持 `1d`；分钟 K 和 tick 不在公开能力范围。
- Market Dumps 提供全市场 10 年日 K、近 10 交易日增量和复权事件，适合回测地基，但仍需真实认证后验证下载、字段、覆盖和质量。
- CLI 能力发现和本地 DuckDB/Parquet 落盘非常适合作为可迁移数据管理参考；但必须把 CLI 版本、数据版本和同步结果纳入项目可复现记录。

### Financial API 真实认证测试状态

当前已通过安全凭证入口保存 API Key，但 OpenClaw secrets store 不会自动成为 `exec` 的通用环境变量；gateway 专家确认需要由宿主机环境管理或用户级凭据文件提供。为避免密钥进入命令、日志、项目文件或对话，尚未进行真实 REST 认证请求。

尚未完成：单标的 auction snapshot、历史日 K、历史涨停池、连板天梯、延迟、并发和错误语义的真实请求测试。

## 8. 当前阶段结论

- TDX 插件目前是三个策略实时/历史分钟行为的首要候选；其历史竞价成交额和历史涨停查询已得到真实工具返回，下一步重点是 9:20 快照和独立脚本化调用链。
- Financial API 是日 K、财务、估值、板块、特色数据和全市场批量落盘的强候选；分钟线和历史 9:20 快照存在明确缺口，不能单独承担三个策略。
- 在数据源最终选型前，必须完成字段级原始响应测试，不能根据本轮抽样结果直接进入策略回测。

## 11. 竞价成交额前 10：脚本化结论

### 首选：eltdx 服务端排序

`eltdx` 可通过独立 Python SDK 直接调用：

```python
with TdxClient(timeout=3) as client:
    table = client.helpers.realtime_rank(sort_by="开盘金额", count=10)
```

底层按“开盘金额”服务端排序，一次只返回前 10，不需要遍历 3000 多只股票。实测约 1.6 秒返回 10 条；同一批股票再用 `quotes.get_snapshots()` 检查 `open_amount_yuan`，与 TDX screener/Financial API 的金额排序结果一致到四舍五入级别。

项目必须在返回结果后显式过滤股票池：仅保留代码以 `60` 或 `00` 开头、非 ST 的普通股票；不能把 `300`、`301`、`688`、`8/9` 等代码混入用户首期股票池。由于服务端榜单可能先返回非目标股票，建议请求前 N（例如 30 或 50）再过滤后取 10，不能只请求 10 后发现过滤不足。

已从插件源码确认并用纯 Python HTTP 实测成功：

```text
POST http://tdxhub.icfqs.com:7615/TQLEX?Entry=JNLPSE:wendaQuery
Header: Content-Type: application/json + token
Body: [{message, rang, pageNo, pageSize}]
```

请求“竞价成交额排名前10”返回 `开盘金额<br>YYYY.MM.DD0#`，与 eltdx 和 Financial API 的 `auction_amount/open_amount_yuan` 排名一致到舍入误差级别。该方案也不做全市场竞价逐股请求，但依赖 TDX token 和 TQLEX 自然语言接口；正式项目应封装响应解析、股票池过滤、日期校验和失败重试。

### 不推荐：Financial API 全市场逐批竞价快照

虽然可通过代码表 + 100 只/批竞价快照 + 本地排序实现，但实测 3196 只股票需要 32 批、约 3.4 秒，且不符合“不要无必要全量获取”的要求；只作为没有服务端榜单时的降级方案。

## 9. eltdx 实测结论（2026-09-05，python eltdx 3.1.3）

安装可用（macOS arm64 wheel，Python 3.14 测试通过），可通过独立 Python 脚本调用，不依赖 OpenClaw 工具，满足可迁移要求。

### 已验证可用（真实请求）

| 能力 | 实测结果 | 延迟 | 用途 |
|---|---|---|---|
| 实时快照 | 2 只股票返回 last_price/open_amount_yuan（开盘金额=竞价成交额）/成交额 | 22ms | 策略一实时 |
| 1 分钟 K 线 | 返回 KlineBar 序列（含时间/OHLC/量/额） | 18ms | 策略二/三分时回测 |
| 历史竞价过程 | `auctions.series(code, date)` 返回 82-84 个时点，含 **09:20:00 精确时点**（price/matched_volume/unmatched_volume） | 47-63ms | 策略一核心 |

| 历史分时 | 每分钟一点，240 点/日 | 23ms | 策略二/三 |

### 关键边界（影响回测）

- **历史竞价过程最早约 2025-10 起**：2025-10-20/10-27 ✅，2025-10-08 ❌。回测起点 2024-10-20 不覆盖。
- 9:25 时点：auctions.series 不含 09:25（为 09:25 前过程），9:25 用 opening_match_history 补充。
- `opening_rush` 字段已出现（如 000892 欢瑞世纪 4.38），疑似竞价抢筹强度，需与竞价涨幅交叉验证。
- `limit_ladder` 传入特定代码返回空行（需要盘中/数据就绪时间），需要重新验证。
- 历史竞价全市场排名：需要按逐股下载再本地排序，或依赖 TDX screener 历史竞价成交额。

### 对三个策略的含义

- 策略一：实时可用；**历史回测只能从约 2025-10 开始**（除非找到 2024-10 的 9:20 历史价格源）。
- 策略二/三：日线/分钟线/分时/涨停价/题材强度均可用，历史连板名单需结合 TDX screener 或选股通。

## 10. 官方完整文档与真实接口测试补充（2026-09-05）

### `llms-full.txt` 的判断

用户提供的 `/workspace/data/quant-research/llms-full.txt` 是 Financial API 官方全站文档聚合，内容比仓库 README 更完整，确认它覆盖许多目标数据，但“文档有端点”不等于“所有策略原始数据均可获得”。

文档确认的强能力：

- A 股实时行情和全市场行情快照。
- 单股历史日 K（当前 `interval` 仅 `1d`）。
- 全市场 10 年日 K 数据导出和复权事件。
- 财务三大报表、财务指标、估值快照。
- 交易日历。
- 指数/板块目录、成分、行情和历史日线。
- 竞价终态/实时快照：竞价价格、竞价涨跌幅、成交量、成交额、未匹配量、竞价换手、竞价量比、昨收和流通市值；单次 1-100 个标的。
- 历史短线风向标竞价基准：按日期返回 `auction_pct` 和 `tags`。
- 历史涨停池、跌停池、炸板池。
- 近 30 个交易日连板梯队矩阵。
- 当日异动原因、热榜、历史热榜走势和龙虎榜。

文档没有提供或明确限制的关键能力：

- 历史分钟 K / tick：公开历史行情端点仅支持日 K。
- 历史 9:20 竞价过程快照：竞价 snapshot 端点只有 `live/final`，没有日期参数；历史 benchmark 只有竞价涨跌幅和标签，不是完整 9:20→9:25 轨迹。
- 历史新闻公告原文和研报：不在公开能力范围。
- 连板天梯是固定近 30 日窗口、每个板位最多返回有限数量，不是任意历史区间的逐股完整数据库。

### 对三个策略的更新判断

- **策略一**：Financial API 能提供当前竞价字段和历史竞价基准，但不能单独提供完整历史 9:20/9:25 轨迹；策略一完整历史回测仍优先依赖 eltdx/TDX。实时建议数据则可用。
- **策略二**：Financial API 能补历史涨停池/连板天梯/日线/财务/板块，但不能补公开历史分钟 K；分钟开盘行为仍依赖 TDX/eltdx。

### Financial API 接入要点（官方 quickstart，2026-09-05 已读）

- 认证方式：REST 请求头 `X-api-key: <key>`；统一在 https://fuyao.aicubes.cn/admin 签发。
- 错误码：`code=2001` = key 缺失/无效；`code=2003` = key 无权访问该 capability。

- 项目内推荐用 `.env`（模板 `.env.example`）+ python-dotenv 方式加载。

2. 用户在宿主机创建官方用户级凭据文件：
   macOS: `~/Library/Application Support/hithink-finance/credentials.env`，内容 `HITHINK_FINANCE_API_KEY=<key>`。

## 13. 选股通题材与复盘接口实测（2026-09-06）

### ① 题材排名：已验证

`GET https://flash-api.xuangubao.com.cn/api/surge_stock/plates` 无需登录即可脚本化调用，返回当日题材列表：`id`、`name`、`description`，以及 `manual_updated_at`、`timestamp`。本次实测返回 13 个题材（养猪/大消费/数字人民币/短剧/大农业/福建自贸/AI大模型/机器人/军工/房地产/云计算等）。

### ② 题材核心表现：已验证

`GET /api/plate/data?fields=core_avg_pcp,plate_name&plates=<ids>` 返回指定题材的 `core_avg_pcp`（核心股平均涨跌幅）和名称，可按题材 ID 批量请求。本次实测传入两个 ID 返回正确。可作主线强度/核心表现指标，但“持续性”需连续多日采集后计算。

### ③ 题材内个股：已验证当日接口

`GET /api/surge_stock/stocks?normal=true&uplimit=true` 返回字段数组和个股数据（代码/名称/现价/涨幅/流通市值/题材/涨停/入选时间/换手率/几天几板/研报字段）。本次实测成功返回。

传 `date` 查询历史时本次返回 `items=null`，不能据此直接认定支持历史回放；题材持续性应先每日落盘快照，再按“连续 3 个交易日上榜”为用户暂定规则计算。

### ④ 新闻快讯：当前未验证可用

`https://baoer-api.xuangubao.com.cn/api/v6/message/newsflash?...` 本次返回 `code=50008`（非法 token）。不能当作免认证新闻源；后续需从选股通页面请求中找到合法 token/调用方式，并记录发布时间、来源和正文可见时间。

### ⑤ 题材持续性暂定规则（用户提出）

- 每个交易日采集题材排名快照。
- 题材在排名中连续出现 3 个交易日，暂定为“有持续性”。
- 必须同时保存题材 ID、名称、描述、排名/顺序、核心平均涨跌幅、采集时间；不只保存名称，避免题材改名或 ID 变化造成误判。

## 14. 东财重点监控/异动接口确认（2026-09-06）

页面 `https://vipmoney.eastmoney.com/collect/min_data/point_stock_monitor/index.html` 为 JS 应用壳，从页面脚本中逆出 3 个可直接脚本化调用的数据接口：

### ① 重点监控证券（最新）

```text
GET https://mobappconfig.securities.eastmoney.com/emcfg/stock_monitor.json
```

返回数组：`MARKET / STKNAME / VALIDATESTARTDATE / VALIDATEENDDATE / STKCODE / LINK_URL?`

实测返回多只重点监控股票（含 *ST 与普通股，监控起止日期完整，部分带公告链接）。

### ② 严重异常波动（UNUSUAL_TYPE=002）

```text
GET https://datacenter.eastmoney.com/securities/api/data/v1/get?reportName=RPT_APP_UNUSUALBASIC&columns=...&filter=(UNUSUAL_TYPE="002")(IS_HIS="1")&sortColumns=NOTICE_DATE,END_DATE&sortTypes=-1,-1&pageNumber=1&pageSize=50&source=SECURITIES&client=APP
```

实测返回深中华A/*ST萃华/天山生物等，含 `UNUSUAL_REASON` 全文、`NOTICE_DATE`、`INFO_CODE`、`PREDICT_START/END_DATE`（预计监控期）。

### ③ 异常波动（UNUSUAL_TYPE=001）

```text
GET https://datacenter.eastmoney.com/securities/api/data/v1/get?reportName=RPT_APP_UNUSUALBASIC&columns=SECUCODE,SECURITY_CODE,SECURITY_NAME_ABBR,UNUSUAL_TYPE,START_DATE,END_DATE,INFO_CODE,NOTICE_DATE,UNUSUAL_REASON,UNUSUAL_REASON_TYPE,MRAKET_TYPE&filter=(UNUSUAL_TYPE="001")&sortColumns=NOTICE_DATE,END_DATE&sortTypes=-1,-1&pageNumber=1&pageSize=50&source=SECURITIES&client=APP
```

实测单页 3 条、总页数 1841（约 9 万+ 条历史），支持分页 → 可重建监管/异动历史清单。

### 约束

东财接口未声明商业授权，仅低频研究用途；调用需带移动端页面 UA/Referer。对“严重监管/龙头负反馈”场景，本数据可作原始监控名单与异动公告来源，具体监管事件影响判定仍需规则层设计。
