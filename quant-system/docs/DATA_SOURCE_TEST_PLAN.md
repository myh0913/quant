# 数据源专项测试计划

> 目标：为三个短线策略筛选可脚本化、数据完整、低延迟、可并发、可迁移的数据源。
> 当前阶段只测试数据源，不修改策略定义，不用近似字段替代策略原始要求。

## 1. 评估维度

每个数据源按字段级记录：

1. 脚本化：是否可由 Python/HTTP/协议稳定调用。
2. 完整性：是否提供策略需要的原始字段。
3. 时间准确性：真实数据时点、服务器时间、可见时间。
4. 历史覆盖：是否覆盖 2024-10-20 至当前，是否支持历史回放。
5. 延迟：请求耗时、数据生成延迟、刷新频率。
6. 并发：批量接口、并发请求、连接复用、速率限制。
7. 稳定性：空值、错误、断线、重试和连续运行。
8. 可迁移性：依赖、平台、凭证和部署难度。
9. 授权与合规：研究/商业限制、账号权限、频率限制。

## 2. 必须原样验证的策略字段

### 策略一：竞价主力抢筹

- 竞价成交额全市场或明确股票池排名。
- 9:20 价格及其时间戳。
- 9:25 价格及其时间戳。
- 9:20 是否低于昨收/0 轴。
- 9:25 是否高于 9:20。
- 9:25 相对 9:20 的涨幅。
- 9:25 相对昨收的实时涨幅。
- 同一时点的股票池完整性。

禁止：用收盘后开盘价、9:25 最终竞价结果或近似快照代替 9:20 快照。

### 策略二：连板捉妖

- 前一交易日收盘后可获得的二连板/三连板名单。
- 次日竞价状态和 9:25 价格。
- 开盘后分钟级价格、成交量、成交额和时间序列。
- 昨日连板票成功率。
- 昨日连板票跌停数量。
- 最近 20 个交易日连板历史。
- 一字板识别所需的价格、成交和盘口字段。
- 启动前成交量、连板成交量及至少 2 倍量验证。
- 连续放量序列。
- 题材、主线、板块和龙头关联。

### 策略三：龙回头

- 二连板以上候选和三板组识别字段。
- 日线首次调整历史。
- 大阴线/长上引线的 OHLC 和成交量。
- 首根阴线与前一日成交量倍数。
- 调整后下一日竞价及分钟线。
- 下跌速度、反复拉升/下跌次数。
- 横盘区间、价格位置和承接指标的原始数据。
- 跌停价格、封单量/额及封单强弱变化。
- 市场情绪、板块集中度和题材分散度。

禁止：把“快速”“承接”“横盘”“出货”等词未经定义就直接声称数据源支持；先确认原始数据，再共同定义计算规则。

## 3. 测试方法

- 每个接口保存原始响应和测试元数据到 `/workspace/data/quant-research/`。
- 记录请求时间、服务器时间、返回时间、HTTP/协议状态、响应大小、字段集合和样本数量。
- 关键历史日期至少覆盖：2024-10-20 附近、近期真实交易日、竞价时段和盘中时段。
- 并发测试使用小规模、逐级增加的方式，遵守服务限制，不做高频压测。
- “可用”必须有代码调用证据；README/网页文档只能标记为“文档声明”。
- 对每个字段给出：可用 / 不可用 / 需替代设计 / 待验证，并说明证据。

## 4. 输出物

1. 字段级能力矩阵。
2. 数据源调用示例和适配器建议。
3. 延迟与并发测试结果。
4. 历史覆盖和 point-in-time 风险说明。
5. 三个策略逐字段可行性判定。
6. 推荐主数据源、备用数据源和交叉校验源。
7. 未解决问题清单，供产品讨论阶段处理。
